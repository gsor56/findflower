Data & integrations

The dataset, the taxonomy, the endpoint

What is available to build on, and what is not yet

The application code is closed. The data is not meant to be. This page documents the file layout, the class index, the licence metadata and the identification endpoint, so that a researcher can work out whether any of it is useful before asking for access.

Access, honestly

The image dataset is on a private repository while per-image licence attribution is assembled and the last classes are collected. There is no public download link yet, and a link to a repository you cannot open is worse than no link, so there isn’t one. Everything below describes what the repository contains and how it is structured; if you need access before it opens, write and say what for.

The dataset

A plain ImageFolder tree. One directory per species, 100 JPEGs inside, filenames prefixed with their rank in the class so ordering is stable across clones. No parquet, no shards, no loader script — it opens with anything that can read a folder of images.

Achillea_millefolium/ 001_<photo id>.jpg 002_<photo id>.jpg … 100_<photo id>.jpg Achillea_millefolium.metadata.json Taraxacum_officinale/ … classes.json curation_manifest.json progress/shard-00-of-05.json README.md

Images per class

Exactly 100. A directory holding any other number is not a finished class and should be treated as absent.

Folder names

The scientific name with every character outside A–Z a–z 0–9 . _ - replaced by an underscore, truncated at 180 characters.

File names

NNN_<photo id>.jpg — a three-digit rank by the composite selection score, then the iNaturalist photo id it came from.

Licences

CC0, CC BY and CC BY-NC only, recorded per image. Mixed, so the set as a whole is non-commercial.

classes.json — index to species

A model outputs an integer. This file is what turns it back into a plant. Keys are the class index as a string, in the order the folders are enumerated, so the map is stable as long as the file travels with the weights.

{ "0": { "folder": "Achillea_millefolium", "name": "Achillea millefolium", "scientific_name": "Achillea millefolium" }, "1": { "folder": "Taraxacum_officinale", "name": "Taraxacum officinale", "scientific_name": "Taraxacum officinale" } }

folder is the directory on disk, scientific_name is the binomial to cite. Read the index as an integer if you sort the keys — JSON object keys are strings, and string ordering puts class 10 before class 2.

The richer taxonomy file

The class list is generated separately from an iNaturalist taxonomy pull, and that generation keeps far more per species than the index needs. One entry, verbatim:

{ "generated_at": "2026-08-16T12:16:56+00:00", "id2label": { "0": { "index": 0, "scientific": "Achillea millefolium", "common_name": "common yarrow", "inat_taxon_id": 52821, "observation_count": 335840, "frequency_rank": 1, "frequency_band": "very_common", "rank": "species", "kingdom": "Plantae", "ancestry": "48460/47126/211194/47125/…", "conservation_status": null } } }

Fields worth knowing

inat_taxon_id

The iNaturalist taxon. Join on this rather than on a name string; synonyms and authority changes move the names around, and the id survives them.

observation_count

Observations at the time the list was generated, 16 August 2026. It is a snapshot and it only ever grows, so treat it as a rank, not a current figure.

frequency_rank

Position in the ranking, 1 to 1,500. This is the class index plus one, since the list was cut from the ranking directly.

ancestry

Slash-separated iNaturalist taxon ids from the root down. Family- or order-level grouping comes out of splitting this, with no second API call.

common_name

English, lowercase, one per species, and sometimes missing or regional. The binomial is the reliable key; the common name is for display.

conservation_status

Present when iNaturalist has one, null otherwise — which is most of the list, because abundant species rarely carry a status.

Per-image licences and attribution

Every class directory has a sibling metadata file holding one record per image, in the same order as the filenames. This is the part that matters for reuse: the photographs are other people’s work, and the licence and attribution string for each one is recorded rather than summarised.

[ { "photo_id": <int>, "observation_id": <int>, "url": "<iNaturalist image url>", "license_code": "cc-by-nc", "attribution": "<photographer, as iNaturalist reports it>", "source_page": "<observation url>", "path": "Achillea_millefolium/001_<photo id>.jpg", "sharpness": <float>, // Laplacian variance "gray_mean": <float>, "gray_std": <float>, "dynamic_range": <float>, "histogram_variance": <float>, "quality_score": <float>, // the six gates, combined "phash": "<16 hex characters>", "cosine_similarity": <float>, // to the class centroid "expected_probability": <float>, "predicted_label": "<audit model top-1>", "predicted_probability": <float>, "audit_rejected": false, "final_score": <float>, // what the 100 were ranked by "label": "Achillea millefolium", "scientific_name": "Achillea millefolium" } ]

The measurement fields are kept deliberately. They let you re-derive why an image was selected, or filter harder than the curation did — a stricter blur threshold, say — without refetching anything.

The served model is a different, smaller thing

Worth being unambiguous about, because the two class lists are easy to confuse. The dataset above targets 1,500 species and nothing has been trained on it yet. The model behind the identification endpoint today recognises 116 species, and its class list is a flat array of English common names in output order — not the binomials above.

[ "common dandelion", "oxeye daisy", "common sunflower", "california poppy", "common poppy", … ]

A response naming a species outside those 116 is impossible; a photograph of one is not. Anything unknown comes back as the nearest of the 116 with a confidence that should be treated as a warning rather than an answer, which is the honest limit of a closed-set classifier.

Calling the endpoint

One POST, one image, one JSON body back. The full reference — keys, limits, errors, the Wikipedia and plant-detail helpers — is on the API page. The shape, so you can judge it from here:

# A bearer token is required. Sign in and pass your access token; # requests without one are rejected with 401. curl -X POST https://findflower-proxy.fofi.workers.dev \ -H "Authorization: Bearer <access token>" \ -F "file=@flower.jpg"
{ "flower": "common dandelion", "confidence": 0.94, "top_k": [ { "name": "common dandelion", "confidence": 0.94 }, { "name": "catsear", "confidence": 0.03 } ] }

Five results, always

top_k holds five entries, softmax probabilities over the 116 classes, descending. flower and confidence are the first of them, repeated for convenience.

Liveness without a token

A GET on the same URL returns { status: "ok" } and needs no credentials. Use it to check the service is up; it tells you nothing else.

One integration detail that will otherwise cost you an afternoon: browser requests are also checked against an origin allowlist, so a fetch from your own site’s front end is refused with 403 even with a valid token. Server-side calls, which send no Origin, are unaffected.

Reuse terms

The photographs

Belong to the naturalists who took them, under the licence each one chose. FindFlower selected and measured them; it holds no rights over them and cannot relicense them. Honour the per-image license_code and attribution — that is why both are shipped beside every class.

Commercial use

The set includes CC BY-NC images, so the set as a whole is not usable commercially. Filtering the metadata down to CC0 and CC BY records gives a smaller, commercially usable subset, and doing that filtering is your responsibility, not the dataset’s.

The taxonomy and counts

Derived from iNaturalist’s public API. Cite iNaturalist as the source of the observation data, and the date the snapshot was taken — 16 August 2026 — because the counts move.

The application code

Closed, and not part of what this page offers. The curation method is described in full on Research, with every threshold, so it can be reimplemented independently.

No warranty

A filtered dataset still contains mislabelled images, and a classifier trained on it will still be wrong sometimes. Do not build anything where a misidentified plant causes harm. The Terms of Service apply.
