Release notes

What’s new in FindFlower.

What changed in the model, the interface and the data the app keeps, newest first. Removals are listed alongside the additions.

Beta 0.9.8

Current 20 August 2026

Dataset & model infrastructure

  • The species list for the next model is settled: 1,500 flowering plants, ranked by observation count out of 5,458 candidates. Collection is well along — 1,003 species and 104,720 verified photos so far, no class under 100 images.
  • Collection runs as five Kaggle shard workers in parallel. Deduplication, quality filtering and the 100-image floor per class happen in the pipeline, so one shard can be re-run without disturbing the other four.

Interface & de-AI refactor

  • Rebuilt the sidebar drawer. The credential badge, the clock and the location panel are gone: the badge showed nothing real, and the location panel asked the browser for your position every time the drawer opened. What is left is navigation, on the standard type scale.
  • Added Blogs and Community as real routes, listed in the drawer and the footer. Both are placeholders for now; Blogs opens with a small botanical drawing animated in CSS.
  • Removed the decorative toggles from the dashboard. Every control left on it reads and writes something real.

Storage & data control

  • The local database moves to v3. The upgrade is additive, so existing rows are not rewritten, and it makes room for deleting a single scan, correcting a wrong identification, and exporting your history as JSON.
  • Streaks and totals are recomputed from the day keys of the records that are still there, so deleting a scan changes the numbers instead of leaving a stale counter behind.

Fixes & code health

  • Router swaps and first page loads now run through one mount path. The dashboard had two ways to start up and could run its setup twice.
  • Dropped the leftover !important overrides and the one-off font sizes; every size on the site is a step on the type scale.

Beta 0.9.4

8 July 2026

New features

  • Identify flowers from a link, including automatic YouTube thumbnail extraction.
  • Developer preview: direct-endpoint documentation and gated API keys via secure sign-in.

Model improvements

  • New Vision Transformer model, now served from a secure hosted endpoint instead of downloading to the browser. Your photo is sent for processing and only the result comes back — this changes the privacy model, so see the privacy page.
  • Expanded coverage to 116 botanical classes.
  • Steadier confidence scoring, with clearer separation between close look-alikes.

Interface

  • Refined result panel with animated confidence and top alternatives.
  • Live Wikipedia context, with reference image and full-article link.

Fixes

  • Resolved model-loading issues on browsers with strict cache settings.
  • Corrected preview handling for large photos.

Beta 0.8.0
